# API 密钥与成本控制

为每个项目或工具单独创建密钥，可以独立停用、限制额度，并更容易追踪用量。

## 创建与编辑

进入 **控制台 → API 密钥**，创建新密钥或编辑已有密钥。按需要设置名称、额度、过期时间、分组、模型限制和 IP 限制；可选项以当前账户界面为准。

| 设置     | 控制范围                     | 建议                   |
| -------- | ---------------------------- | ---------------------- |
| 额度     | 该密钥可消耗的额度           | 初次接入先给小额度     |
| 过期时间 | 密钥的有效期                 | 临时任务设置短有效期   |
| 模型限制 | 该密钥允许请求的模型         | 只开放项目需要的模型   |
| 分组     | 请求使用的可用资源与计价配置 | 结合模型广场查看       |
| IP 限制  | 请求来源                     | 仅在出口地址稳定时设置 |

密钥额度和账户可用额度是不同的限制。密钥还有额度，不代表钱包或订阅一定可支付。

## 控制持续运行的任务

先跑一个小任务，在「使用日志」核对实际模型、输入输出 token、缓存信息与扣费。确认后再增加任务规模。Agent 多轮推理和工具返回内容会增加上下文，长时间运行前应检查额度和到期时间。

使用额度、模型限制和有效期控制支出，并定期查看价格与用量。额度限制不等于锁定模型单价。

## 密钥泄露或轮换

发现泄露后立即停用或删除对应密钥，创建新密钥并更新使用它的工具。检查泄露期间的使用日志。删除仓库中的明文不足以阻止旧密钥继续使用，历史提交中也可能保留副本。

不要在浏览器公开代码中调用携带真实密钥的 API。应用应由自己的后端保管密钥，前端只访问你的业务接口。

## 请求被拒绝

查看响应中的错误信息，再核对密钥状态、有效期、额度、模型与分组权限。权限或额度问题应先修正配置，反复重试不会恢复访问。状态码说明见 [常见问题](/guide/faq#常见错误)。
